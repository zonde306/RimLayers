## 1. 目标、依据与范围

D0 不生成空壳 DLL、玩法代码、工程或启用配置；后续工程和玩法按 M1–M5 实施。建档交付与后续实施分阶段记录，保留已有实现和有效证据。

新验收场景初始状态统一为“未验证”。已核实接口、计划契约和运行结果分别记录；实际结果、候选版本与输入记录在实施日志，不由计划表自动标为通过。

目标是在单张真实 Map 内支持多个逻辑楼层，让 Pawn 跨层寻路、搬运、选择物品/家具/工作台、多次取料、工作及战斗。楼梯/单层电梯逐层通行，垂直电梯可沿贯通井道直达；经过中间层不改变最终目标与正常工作的同一 Job。人工高层楼板必须遵守紧邻下层已有有效屋顶的规则；山体天然楼板独立承载。

项目名称、程序集和命名空间均为 `RimLayers`，包标识 `rimlayers.core`。面向 RimWorld 1.7 / Waylith / net10.0，初期一个程序集，按模块组织源码。当前本地实施基准为 1.7.4982 rev1280；历史 M1 验收使用 1.7.4980 rev60，旧版方法快照不能替代当前成员核实。

## 2. 空间模型与显示

### 2.1 单 Map 坐标布局

每个殖民地仍使用一张真实 Map，Thing / Pawn 只存在一份，在楼梯口不执行 DeSpawn/Spawn。游戏会话仍可拥有其他 Map，不把所有殖民地合并。

令地面逻辑宽高为 W、H，楼层数为 L：

- `stride = ceil((H + 1) / 17) × 17`，作为本项目的分带与分块对齐策略。
- 内部楼层 `layerId` 从 0 开始，界面显示 `layerId + 1`。
- `LayerCell(layerId, x, z)` 满足 `0 <= x < W`、`0 <= z < H`、`0 <= layerId < L`。
- 存储位置为 `IntVec3(x, 0, z + layerId × stride)`；Map 存储尺寸为 `(W, 1, L × stride)`。
- 每个坐标带中 H 以外的尾部、带间空隙都属于隔离区域，不能反解为可用 LayerCell。
- 同一局地图的 W/H/stride 与布局版本固定保存；L 只能通过追加事务增至三层，不支持缩减或重排。

布局只定义地址，不代表上层已经有可站地面。上层一般为空域；厚顶岩轮廓内按需生成不可拆天然楼板与含矿岩体，开采后形成同层空间。薄顶岩不自动生成楼面。人工楼面及连接器平台仍通过结构规则建立。首个楼梯出口采用专用的平台施工流程，仍需验证对应下层屋顶，不能自动铺满上层。

隔离区不能被用作移动、放置、射线、气体、光照、电力、天气抽样或世界出口。逻辑空域与存储隔离区必须区别处理：空域可以依规则透光、传气，但不是可站地面；隔离区没有物理意义。

### 2.2 三种坐标与目标身份

- 存储格仅用于原版 Map 数据访问。
- 逻辑格用于楼层身份、路径、邻接、交互和规则判断。
- 战斗几何坐标在逻辑 x/z 之外引入楼层高度；显示高度和物理高度明确映射，不从存储带间距推导射程。

所有空间规则经过 Layout 或领域服务，不全局替换所有距离函数。纯格子目标保存楼层与局部格；Thing 目标保留真实实体引用，并通过 `MapHeld / PositionHeld` 按业务规则处理容器。Blueprint→Frame→建筑及堆栈拆并必须在确有实体转换时重绑定目标。

### 2.3 普通视角楼层切换

使用二维普通视角，保存局部观察位置，切换相机至目标坐标带，限定相机及点选边界。高层空域另行投影真实下层地形、静态网格、可见 Pawn 与尸体，按深度叠加动态半透明雾纹理；本层不透明结构楼面和装修地板盖住背景，原版迷雾仍有效。背景使用自有材质副本与独立绘制队列，不修改共享材质。动态实体保持真实绘制输入，在最终网格提交时只投影一次，包含装备及自定义 PostDraw；不拦截肖像/图集的即时绘制。背景不改变实体位置、AI 或碰撞。缩放、拖动、跳转 Pawn 和切图经过同一适配。跨层跳转在原生相机居中之前切层，取消旧平移及惯性并立即定位；同层保留原生平滑平移。瞄准和面向使用逻辑平面向量，保留真实目标、原生武器姿态和 Verb 角度覆写；自定义武器共用入口只修正有效跨层瞄准。

F7/F8 通过原版 KeyBindingDef 提供可重绑定切层入口，保留面板及 Alt+方向键。楼梯实体在上层出口绘制下行图标与按钮，不复制 Thing。普通拾取、建造和格子命令限查看层；攻击模式可从无遮盖的下层背景取得真实 Thing，瞄准线与高亮投影到屏幕所在层。

查看层只影响表现和命令拾取；不修改实体位置、不把所选层作为 AI 查询范围，也不把 UI 状态当作模拟事实。命令目标由点选格解码为真实存储目标，不能重复加偏移。三维叠层渲染作为可选后续模块，不进入首版依赖。

## 3. 模块边界、接口与所有权

`LayerMapComponent` 是每张受管地图的组合根，持有地图布局、自有事实与服务实例。组件缺失或地图不受管时，补丁维持原版行为。游戏对象操作和状态提交遵循原版线程上下文，不能随意移入后台 Task。

下表规定内部契约；其中部分已有实现，具体落地状态以实施记录为准。参数和返回类型应在各阶段按当前原版签名落实，不把名称当作原版 API 或公开稳定 SDK。

| 模块 | 主要职责与最小契约 | 状态归属 |
|---|---|---|
| Layout | `TryDecode(storageCell)`、`ToStorage(layerCell)`、边界与隔离区判断 | 布局参数与版本持久化 |
| Topology | `GetMovementEdges`、`ValidateConnectorStep`、连接器注册/移除；方向、能力、开闭与版本 | 连接器实体/配置为事实，邻接图派生 |
| Navigation | `FindRoute`：完整端点搜索、原版层内路径及拼接；保留最终目标、路径结束模式和自定义路径约束 | 当前路径和成本缓存派生 |
| Work | `EnumerateCandidates`、`EstimateTravelCost`；适配 Thing/格子/材料/食物/床/家具/储存，保留业务规则 | 目标由原版 Job 持有，索引派生 |
| Structure | `ValidatePlacement`、`ValidateCommit`、`InvalidateSupport`；逐格屋顶、楼板、装修和天空列 | 自有结构事实及必要的待处理失效状态持久化 |
| Combat | `CanHit`、`FindFiringPosition`、`TraceShot`；射程、LOS、护盾、弹道、近战和爆炸 | 必需的发射/提交事实持久化，几何缓存派生 |
| Environment | 电力链接、设施范围、空气/热、天空暴露、天气、游戏光照 | 配置/必要事件状态持久化，网络派生 |
| Presentation | 查看层、相机约束、绘制过滤、点选和命令位置转换 | 查看状态不作为模拟事实 |
| Persistence / Diagnostics | 数据版本、加载重建顺序、失效传播、日志及调试覆盖层 | 不重复拥有原版 Pawn / Job / Thing |

模块依赖按“使用者依赖被使用者”理解：

- Topology、Structure 依赖 Layout，分别拥有连接事实与结构事实。
- Navigation 依赖 Layout、Topology 与 Structure 的通行查询；Work 依赖 Navigation 的可达性/成本及原版业务规则。
- Combat 与 Environment 依赖 Layout、Structure 及各自授权的 Topology 查询；寻找可到达射位时由 Combat 调用 Navigation，不把可达性作为射击的前提。
- Presentation 读取领域服务并发出普通命令；领域服务不依赖 UI。Persistence / Diagnostics 通过组合根编排保存、重建与观测，不另存一套原版业务对象。

Structure 的变化通过定向失效通知影响其他服务，不反向调用它们，也不形成逐 tick 相互扫描。

Topology 按移动、空气、热、电力、声音和火焰分别表达许可，不能因为两个格子有楼梯就同时允许所有传播。所有权集中在组件，避免多个服务各存一份布局或原版实体深拷贝。Harmony 接入层只做范围判断、参数转换和领域服务调用，Def/Comp 能解决的行为优先使用 Def/Comp。

## 4. 核心流程与失败处理

### 4.1 导航、连续工作和仲裁

可达性与最短路线分离：`CanReach` 对层内边复用原生区域可达性与缓存，对跨层连接仅进行全部合法楼梯端点的连通搜索，不生成 PawnPath；目标末段保留原始 PathEndMode 与 TraverseParms。原生同层可达可以提前成功，失败仍须允许经其他楼层绕回。同层边沿用原生规则，销毁/水域等特殊模式仍由原版处理。该查询不选择最佳路线，不缓存跨查询业务结果。实际移动及明确需要实际路线成本的比较继续执行下述完整 Dijkstra，不能以可达性或直线距离代替路径成本。实现与运行证据见 [0.1.3 可达性修复](REACHABILITY-VALIDATION.md)。


1. 原版业务规则选择真实目标，建立原版 Job、材料队列和预订；Work 适配候选范围与成本，不绕过禁用、容量、阵营、工作优先级或物品数量。
2. 各个 Goto 交给 Navigation。端点图采用 Dijkstra，层内边成本来自实际原版路径，跨层边来自合法连接器；不截断为最近几个楼梯，不要求楼层方向单调。
3. 拼接保留原版最终 Destination、EndMode、通行规则及 `IPathGridCustomizer`；层内调用避免再次进入跨层路由。无合法路线则按原版业务失败处理，不能静默放松约束。
4. 非相邻跨层步记录连接器身份与版本；进入前再次检查两端、方向、通行能力和落脚格。
5. 拆梯、楼板失效或端点变化时更新图版本并清理原版可达缓存；门权限实时读取原版 Region.Allows，不跨请求缓存。已持有路径在跨层提交时按原始 TraverseParms 再检查，先重规划，失败后结束相应工作。

普通跨层移动保留同一 Pawn / Job / Driver / 预订，楼梯口不是阶段完成点，不引入跨图 Travel Job 或第二套远程预订。多次取料继续使用原版 DoBill 材料队列和 Toil 循环，完成产品后保留正常入库交接。

工作与需求查询逐入口适配，不能仅改 CanReach：包括格子扫描的距离过滤、工作台选料的独立半径、食物评分、床的归属/医疗优先、娱乐容量，以及普通仓库和容器。近距离交互、放料和额外顺手拾取需区分同层邻接与跨层可达。

饥饿、休息、紧急行为、征召、玩家取消及强制命令服从原版仲裁；不在高优先级节点无条件恢复普通工作。确需自有复杂计划时使用独立请求代次，旧回调不能复活已取消任务。牵绳、机体控制范围和 Lord 职责作为单独适配点，不假设同 Map 已自动正确。机体控制距离使用逻辑平面距离，保留原版操控者、MapHeld、地图边界和距离阈值；指挥圈只将原版绘制中心投影至查看层，谓词与模拟采用相同距离。机体正常过层保持原生操控关系和控制组，不复制成员。

牵绳沿用原生 RopeToPen / FollowRoper、同一领队 Job、多个动物引用与预订。楼梯对未被真实牵引的原生 fence-blocked 放牧动物按围栏门处理；牵引者的预先查询及 PassDoors 查询仍可评估合法路线。畜栏不合并上下层 Region，最近畜栏按实际牵引路径成本比较，营养平衡模式和原生过滤不改。取消、征召和断路交还原生断绳/清理；取消后正常工作树可以选择新的工作，不能将新 Job 的预订误判为旧任务复活。

Lord、成员与职责仍由原版唯一持有和保存。正常过层不移除/重新加入成员，不另建分层子 Lord；职责目标保留完整存储格。原生 Travel 的临时防御会在无伤害 1200 tick 后返回原行程，永久改派应更换同一 Lord 的业务 Job，而非只改临时防御点。死亡等真实损失继续通知原版。


### 4.2 严格屋顶建造与结构失效

普通高层建筑对旋转后全部占地检查有效楼面。人工楼面要求紧邻下层已有人工或薄岩屋顶及当前支撑；天然楼板独立承载，不因下层塌顶消失。厚顶岩不改成薄顶，上层岩体必须真实开采；薄顶岩上方必须自铺楼板。默认不引入建筑重量模拟，支撑按逐格屋顶与结构有效性判断。

蓝图放置、供料、施工和完工提交共享逐格屋顶及结构事实。规划阶段允许在全部有效下层屋顶上一次拖出整片结构楼板蓝图，并显示绿色边界；规划不要求邻接已建楼面。供料、施工及完工仍要求真实可用邻格，不把蓝图当作已建楼面；工人从边缘推进，尚未连通的蓝图等待后续楼面。普通建筑不放宽楼面资格。

最终 guard 必须早于 `Frame.CompleteConstruction` 的材料销毁、Frame 销毁与完成信号。检查失败时保留合法的 Frame 和材料，并显式结束当前施工尝试、释放对应工作预订；不能只跳过 void 方法后仍让 Job 判为成功，也不能逐 tick 重试产生刷屏。

屋顶/楼板失效立即撤销相关可站立、施工和遮挡资格，再排队处理连锁影响。队列按实体去重，事故坍塌与正常拆除分别定义物品、携带关系、伤害和退款规则，副作用只提交一次。下层 RoofDef、上层结构楼板、装修地面分别记录，不由单一 TerrainDef 推断全部结构事实。

天空来袭物按自身及直接内容物的旋转占地，从最高层向下寻找首先接触的有效楼面；各部分使用同一撞击层，不按每列分拆实体。结构楼板中止下落，首版不模拟物体重量或贯穿楼板。薄顶沿原版破顶阶段处理；更高层空域上的屋顶也必须检查。实际进入、破顶、撞击前按当前结构复核，不重启动画倒计时；随机落点的普通与非站立模式均拒绝隔离区和被更高楼面遮挡的坐标带。

落地/开舱只向本撞击层的完整有效占地放置。普通 Near 搜索不以擦除已有建筑或 Frame 作为兜底；可清理污物沿原版处理，真实物品先完整规划本层安全挪位，再提交。没有位置时保留原版 holder 中的同一实体，给出清理/扩建楼面的提示，按 30 tick 重试。显式指定的直落/Wipe 模式保留原版语义，但不能为物品挤出而删除已有货物，也不能把舱壳或 Pawn 放进实墙。

原版 Skyfaller.hasImpacted、hasHitRoof、倒计时及 holder 继续唯一保存业务阶段。撞击后的重试只处理剩余内容物，不再次爆炸；穿梭机的蓝图清理延迟到实际可放置时，而不是每次失败重试都执行。部分卸货后，若原版已移除舱壳，则恢复同一舱壳及剩余内容物；只在该恢复调用中跳过原版“挤出旧物品”的容量分支，不改变全局游戏状态或普通仓储容量。

世界出口使用地面逻辑边界。隔离区与上层存储外沿不是离图出口。Best/Random/Near 入口和区域出口可达性接入逻辑地面及合法楼梯，保留原版验证器/通行参数；Goto、Flee、TakeAndExitMap 的实际执行委托使用同一出口几何及方向。加载时不以尚未恢复的布局决定是否永久安装 Toil 检查。家园仍走原版商队组建及出口附近集合政策，不启用本来关闭的 ExitMapGrid；飞行、传送和运输保留原生离图资格。

### 4.3 战斗

点选使用真实 Thing，不复制低层目标到高层。Combat 分开处理当前可射击、寻找可到达射位和继续追击；缺少步行路线不直接等同于不能射击。

三维战斗实施规则见 [三维战斗与验收](COMBAT-3D.md)。层高为 3，普通直射有效射程为原射程 × clamp(1 + 0.1 × 层差, 0.8, 1.2)，曲射/投掷保持原射程；最小射程与精度使用实际水平距离，不修改伤害或穿甲。沙袋/路障独立逻辑高 1.0。跨层直射用九点身体暴露及完整路径遮挡，保留原版精度/散布，三维掩体只结算一次；同层普通射击保留原版掩体。枪口、射位 AI、炮台索敌、实际发射与显示共用结果，不新增平台探身。近战限同层真实 Touch，命中提交前复核。

有人炮台保留原版操作、取弹、装填、供能、冷却与预订，使用真实跨层路线到达原版操作位；物理发射点是炮口而非操作员。迫击炮检查整列发射净空和连续三维弧线，同层起终点也不能跳过上层空间。区域轰击允许预判屋顶截击，实际散布弹丸在首碰撞处走原版弹药效果。

范围盾默认采用覆盖所属楼层的有限高度圆柱，半径沿用原版。护盾耐久与敌我判定仍由原生 CheckIntercept 执行；在其返回后记录最终拦截结果，不把尚未作出的判定预先存为成功。大 delta 的扫掠游标只推进到已处理的接触点，未处理的后段在读档后继续。绘制与原生裁剪均读取已消费接触点，不为显示修改实体的模拟位置。弹丸保存不可变的发射快照和必要提交状态，不能在绘制时从已移动的发射者重新推算起点。沿原版伤害链提交一次，区分个人盾与沿途范围拦截器；爆炸采用三维距离计算覆盖、到达时间、衰减、排除半径和气体范围，复用同一个原版 Explosion 的待处理格与已受伤实体集合。覆盖在引爆时冻结，本次爆炸破坏遮挡不让同一波追溯穿透；读档继续队列，不重新 StartExplosion。LayerBlast 仅补存物理爆心和原版未序列化的气体数量/范围。爆炸原有总热量按冻结覆盖格分配至实际房间，只在原版 StartExplosion 的一次开始阶段注入；读档不重放开始阶段。

人工屋顶即使跨在本层无楼面的空气上，也仍是物理遮挡，不能把“本层可站立”作为屋顶存在的前提。

实心表面的命中点沿弹丸来向回退 0.0001 个逻辑长度单位，留在撞击一侧的空气体积；障碍所属层只用于找到被击实体，不能直接当作爆心所属层。物理高度可在最高屋顶之外，存储位置仍投影到有效坐标带，不把真实爆心夹回屋内。火花的点火副作用使用实际命中的占地边缘格，保留原版点火流程。

### 4.4 公共系统与存档

电网使用逐层建造的垂直端子：相邻层、相同局部 x/z、两端启用且有有效楼面时扩展原版 BFS 邻接。关闭端子同时切断该格的本层输电，沿用原版开关语义。两条连接成环仍只有一个原版 PowerNet，能源由原版发电机、用电器和电池结算；不保存网络实例或生成虚拟电源。端子配对由已保存的位置确定，开关由原版 CompFlickable 保存。普通设施限同层；逆重飞船专属设施在同船结构内按逻辑距离跨层关联，保留全船数量上限与各设施生效条件。

实心结构楼板阻挡气体与直射；无楼板且无屋顶的开放井口连接上下空气体积。楼梯通过 Def 扩展分别授权空气和热，不从移动许可推导电力/空气权限；气道两端的关闭门会阻断传气，Pawn 的禁止标记不影响通气。气体每 30 tick 对活跃列作一次等体积快照交换，各通道源扣目标加且保持 0..255；一浓度单位以内为离散平衡。BlindSmoke 保留原版不扩散策略，其他通道保留原版 DLC 掩码。自有竖向转移守恒，原版源汇与耗散另算。浓度只由原版 GasGrid 保存，活跃索引读档重建。热交换、气体和光照不得跨越隔离区传播。

热交换保留独立原版 Room 和原版温度存储。每 120 tick 的原版温度阶段后，按当前房间温度快照对共享面计算一次等量反向热量；容量使用原版 CellCount（热量单位为温差 × 格数）。原型每格每阶段导热系数 0.006、开口/授权楼梯对流系数 0.084；关闭门回到慢速楼板导热。每个有限房间单步总混合份额不超过 0.25，避免多边同时抽取导致过冲或依赖枚举顺序。室外房间作为无限热库，不宣称包含室外源汇的总系统守恒。低层天花板改与实际上层空气交换，不再同时应用原版薄顶/无顶向室外损耗；最顶层保留原版室外损耗。隔离区 RegionType=None，原版墙体换热采样也排除隔离格。

天空暴露逐列检查本格屋顶与所有更高有效楼板/屋顶。该查询用于房间露天比例、雨雪/沙、气体耗散、雨水灭火、游戏 GroundGlow 与照明网格；不全局替换 Roofed，也不写假屋顶。天气噪声按局部 x/z 采样，实际积雪仍写本层原格。原型人工灯光限层内，隔离区的原生 blocker 防止串光；跨洞口的人工竖向透光是后续明确适配项。遮挡变化刷新相关列的显示，数值与实际画面分别核对。

火焰与惊扰分别使用独立连接器权限；可共用开口/门的物理资格，但不借用 Pawn 通行或禁止标记。火焰保留原版 TrySpread 的调度，每次原版扩散尝试追加一次竖向检查，选一个可燃合法落点：向上概率为原版可燃概率 × 0.2，向下 × 0.05。井口无楼面时先经过开口，再向邻近有效楼面传播，不在隔离区或悬空格生成静态火。新火使用原版 FireUtility，保留 instigator 与原版火焰存档。

惊扰保留原版同层回调，跨层追加有界声路 Dijkstra；水平直/斜邻接代价 1 / √2，逐层代价 3，关闭门与完整建筑阻断，不穿双墙对角。听力缩放有效预算，每个远层 Pawn 只回调一次。该接口传播游戏惊扰，不改引擎的实际音频混音。

危险爆炸的跨层预警采用物理 9 格范围与三维遮挡，保留智力、阵营、伤害类型及 instigator 过滤。逃离保留征召、爬行与强制命令仲裁；候选安全距离至少 9 格，且在已知爆炸半径外再留 1 格。按离 Pawn 的逻辑距离枚举局部半径“安全距离 + 3”内全部合法楼层候选，再调用完整导航，选首个可达安全格建立原版 Goto / Sprint。没有该范围内的合法目标则不伪造可达性。通知仅记录强制任务期间的危险，不为此触发整个 ThinkTree 抢占原命令。加载后从原版已启动引信/已落地延迟弹丸重建待通知列表，首次正常模拟时再通知，不重启倒计时。

保存布局、自有结构事实、连接器必要配置、尚未完成的领域事件和必要的战斗事实；不重复深存原版 Job、Pawn、Map 或物品。Def 用 Scribe_Defs，已有实体用 Scribe_References，自有对象按唯一所有者使用 Scribe_Deep。房间温度沿用原版逐格存储与 1/16°C 向零截断，不另存高精度副本。

未扩层旧地图直接沿用原生加载，不在 `Map.ExposeData` 改写 XML 或预分配楼层。完成首座楼梯/单层电梯后，在原生材料提交前执行 `EnsureLayerCount`；成品生成/加载请求安全地图 tick。已有布局只追加缺少的层，不能清空旧上层；回滚恢复原布局、原区域图及屋顶生成队列，重建天空派生缓存。

`GenSpawn.Spawn` 对新生的非飞行 Pawn 检查真实楼面；非法落点先查同层真实安全格，再退到地面。`Map.FinalizeInit` 结束时恢复存档里已处于空域的非飞行 Pawn，保留实体/装备，只结束失效工作；合法落点和飞行不受影响。

加载顺序为恢复布局与事实 → 等待实体引用可用 → 重建结构/连接器与索引 → 重建路径、网络和几何缓存 → 恢复安全模拟。已提交的伤害、材料消费、产物与退款不能重播；版本不匹配不得静默重排旧地图。

## 8. Odyssey 逆重飞船扩展（2026-10-19）

采用原版 Gravship 作为跨 Map 载荷与唯一实体所有者，补充实际甲板跨度与核心偏移。`ShipStructureService` 的原始结构图不查询原生有效基架或设施生效状态，避免延展器递归。核心可以位于任意层；上下楼面都属于同一船体，最低甲板作为载荷相对第零层。原生核心层二维基架查询与全船归属分离，全船格数共同计入承载量。

上层使用专用 `RL_ShipStructuralFloor` 基础层，允许装修；普通区域仍用通用结构楼板。旧船楼板在安全模拟阶段幂等转换；船外相邻普通楼板不得被横向吞并。新增楼板登记事实后必须刷新本格原版路径缓存。完整状态、实际证据与运行边界见 [多层飞船与电梯](DECKS-AND-ELEVATORS.md)。

### 按需创建、屋顶与电梯

连接器完工前准备所需上一层，失败保留框架与材料；新地图和未扩层旧档均不预建。合法飞船在确认出发后、扣油前一次准备实际载荷所需层数，选择及取消不改地图。追加保留原有坐标、实体、Job、Driver、预订和已有上层内容。

下层屋顶使用不透明、分区缓存的表面遮挡背景实体与点选；本层楼板覆盖屋顶背景。不改变屋顶事实和弹道。相机、迷雾与交互仍由现有统一入口处理。

两种电梯共用 `ConnectorEdge`，保留楼梯兼容入口。单层电梯 25/180 tick；垂直电梯每层建构件，关闭中间停靠保留井道，通电 `30+45×层差`、应急 `90+120×层差` tick。Dijkstra 比较步行与通行总成本，跨层提交前复核同一连接器；电梯不桥接电网，也不授权空气、火或热通道。仅生成的拆除/坍塌返还材料在无法安全放置时暂存数量并保存，清理后重试，不复制原版持有物品。
