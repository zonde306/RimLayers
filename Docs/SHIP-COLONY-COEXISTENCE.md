# 飞船与普通楼层共存：实施契约

2026-10-19；目标 RimWorld 1.7.4982 / Waylith / .NET 10。状态：共存主体已实施；2026-10-20 补充停靠高度上限规则。各项实际验证状态见 [验收记录](SHIP-COLONY-VALIDATION.md)。

## 建造与空间归属

- 普通高层结构楼板上允许建原版逆重飞船基架，再建引擎。仅该起始路径局部放行基架的已有引擎/范围前提；保留研究、材料和真实支撑。
- 飞船结构楼板仍需已有有效引擎，只用于对应船体的上层扩建；不能用引擎蓝图或无主飞船楼板启动新船。
- 普通/飞船按实际格归属，不按整层、引擎距离或垂直投影自动认领。已有普通楼板不能直接叠建飞船上甲板，反之亦然；普通楼板与飞船楼板允许横向对接。
- 明确例外是船底基架覆盖普通停机坪。普通楼板及装修保存为地图侧底层；飞船离开后恢复。不得把停机坪底层混入载荷。
- 原生屋顶支撑与船体归属分别检查。允许有合法屋顶支撑的船体伸出下方飞船范围；普通楼板不传递船体归属。

## 连通与多船隔离

- 同层飞船楼板四邻接分块；每块寻找下方同船合法锚点。向下查找允许跳过连续镂空，不能穿过普通楼板、天然实体或另一艘船。
- 任一格有合法锚点，整块可属于该船；不是要求块内每格下方都必须是飞船。最终必须连到有效引擎，孤岛不能自证合法。
- 例一（自上向下）`空船空船空 / 空船船船空`：上层断开的两块均随船。
- 例二 `空船船船空 / 空船空船空 / 空船船船空`：镂空保持为空，船体整体可随船。
- 例三 `船船空船船 / 普船船船普`：满足原生屋顶支撑时，上层左右整块均可随船。
- 例四 `船普船空船普船 / 普普船船船普普`：上层最外两格不能归入本船，中间两格可随船；普通楼板不作为连接桥。
- 每船保存独立身份，落地保留身份；建造按明确选择的引擎归属。相邻/上下接触的两船不能合并，不能用另一艘船承接自己的孤岛；设施、承载、登船和载荷分别计算。多候选时不能按距离/遍历顺序抢占。
- 断连楼板留原地，不自动改普通楼板；拆建、屋顶、引擎/归属变化和读档使连通缓存失效，最终捕获前重新核实。

## 起飞分离

- 起飞只带走本次有效随船格及原版允许的实体，普通楼板保持；建筑按完整旋转占地判断。
- 全部在随船格内的建筑按原版处理，全部在留下格内的建筑留下；跨移动边界的建筑摧毁，包括跨普通楼板或本船断连楼板。
- 不在预览、CanLaunch、目的地检查或取消时销毁。确认说明损失，最终载荷构造前集中扫描去重并销毁；扣油前检查失去这些建筑后仍能起飞。
- 成品销毁而非完整拆除退款；框架取消只退实际投入，蓝图取消。原版容器内容、掉落物保持真实对象，安全放在岸侧；没有空间时以地图 ThingOwner 暂存并保存，不复制也不把它们误带走。
- 船外普通楼层依赖离船支撑，或留下的楼板挡住垂直起降通道时阻止起飞。普通跨界区域沿用明确拒绝，未授权自动切割。

## 高层停靠、载荷与存档

- 允许在地表以上普通人工停机坪或有合法下层屋顶支撑的空位停靠，不新增无支撑悬停。最高海拔为 +9；新增受单图设置、全局配额及太空扩层开关限制。地下层不增加地上高度上限。
- 查看层决定船底落层，提交后固定；绝对层=落层+载荷相对层，引擎保留相对高度。真实 Map y=0，按目标 stride 编解码。
- 停靠最高层 = 船底停靠层 + 载荷垂直跨度 − 1；镂空层仍计入跨度，按物理高度计算，不能把地下层或存储 LayerId 计入地上高度。
- 最高海拔超过 +9 时拒绝停靠，不截断上层、不压缩镂空层。两层船以 +8 为底占用 +8～+9（仍需满足新增配额）；以 +9 为底则需 +10，拒绝。
- 超限预览标为无效，显示占用层范围和地图最高层；确认着陆与最终放置复用同一高度检查，均在扩图、平台覆盖和生成实体之前执行。失败保留飞船及停靠标记，允许换层重选，不开始着陆、不修改地图或载荷。
- 尚未生成所需上层时，预览只读；出发确认在扣油和拆离前预留额度，到达接收时分配。已在途及有效预留保全原承诺；选择更高落点的额外层必须重新检查。载荷最多跨六层，详见 [设置与恢复](SETTINGS.md)。
- 单甲板原版船同样支持；船底原版基架不因位于高层就自动变专用上甲板。旧版本1/2飞行存档继续可读。
- 预览只读；确认后按需追加层数；完整占地检查逻辑边界、迷雾、禁建区、实体、原生屋顶支撑及垂直净空。不能用起飞销毁规则清空着陆建筑。
- 覆盖记录只在地图保存；原版继续唯一持有飞船实体。逐格覆盖/释放及拆除/摧毁仅处理一次，失败恢复本次地面修改，结束后重建路径、连接器、电网、空气/天空。
- 无历史覆盖记录不得虚构停机坪；旧通用甲板通过显式转换预览处理，不持续自动认领。
- 保留原版燃料、研究、设施数量、推进器、冷却与航程规则。原版逆重锚政策不变：无锚强行起飞视为放弃地图，不自动保留混合基地。
- 延续二维起降动画，修正高层捕获/相机/落点定位，不新增完整三维动画。

## 实施顺序与验收

1. 船体身份与连通算法、示意图纯测试、隔离两船、去除旧自动转换。
2. 高层基架起造与普通平台覆盖/释放持久化，保持上甲板引擎前提。
3. 移动边界分类与真正起飞的销毁/容器回收；只读预检及原版确认接入。
4. 高层目标上下文、选址/确认/放置、原版单甲板及不同stride、旋转、追加/取消。
5. 隔离游戏场景：示意图、断开/补回、双船相邻/上下重叠、真实施工、跨界2x1各朝向/框架/容器、覆盖停机坪保存加载与往返、支撑/净空拒绝、地面起降与无锚地图放弃；实际检查画面。

编译、纯测试、游戏测试与画面检查分别记录；未验证项不得标完成。不要修改玩家启用列表或存档，不复制游戏/Harmony DLL。
