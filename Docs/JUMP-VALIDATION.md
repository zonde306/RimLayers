### 已覆盖的行为

- 无楼梯/电梯连接，仍可从平台边缘上跃和下跳；地表↔二层、地表↔三层、二层↔三层均实际抵达。
- 同层使用原版 PawnFlyer，原生落地不变。
- 楼板下方直接上跃、厚顶、地表→地下、飞船甲板、空域落点均拒绝；几何测试另覆盖独立屋顶、中间楼板、体宽/头顶及负海拔。
- 真实 `CastJump` 下单、原版预热、原版扣次数与新载体衔接；预热途中出现真实阻挡后不扣次数。
- 飞行中新增屋顶、大 delta 扫掠、落点楼板被撤掉时，不穿板、不丢人物，改落在同侧合法承托面。
- 人物仍在飞行器中时，选中人物可取得“重试安全着陆”动作，执行回调后实际着陆。
- 人物已放出、货物仍在容器的部分放置失败：拒绝销毁带货载体，之后可实际重试放出原货物。
- 无携带事务作用域泄漏。
- 原始 43 银堆在飞行保存、退出游戏、重新启动读取、着陆后保持同一 ThingID/数量，并回到携带者；不重复扣次数。
- 原生排队 Goto 在落地后恢复为同一 loadID，征召/自由开火状态恢复，空飞行器清理。
- 新 Def 和全部补丁在不启用 Royalty 的 Core 配置中加载，原有射击与在途存读档继续通过。

## 保留的失败与修正

- `v1-jump-20261021-042025`：2 项失败。携带物夹具误将仍 Spawned 的银堆传给 bool 版 `TryStartCarry`，未检查拾取成功；改用原生数量重载并先断言原物品已被实际持有。队列失败是实际生命周期问题：原生 RespawnPawn 恢复队列后又做覆盖查询，Goto 被 Wait_Combat 替代；改为原生落地查询后恢复队列。
- `v1-jump-20261021-042306`：4 项失败，保留上述错误夹具及落地作业详情。未放宽原物品、数量、原队列身份断言。
- `v1-jump-20261021-042444`：42/11 项通过，验证携带和队列修复；后续新增故障恢复与 UI 探针，使用最终目录交付。
- `v1-jump-20261021-042646`：预热动态屋顶断言失败。夹具屋顶位于 x=51，人物到该格时头顶尚未到屋顶平面，轨迹本来畅通；移到真实相交的 x=53，并增加“当前目标确实已受阻”的前置断言。
- `v1-jump-20261021-042756`：55/11 项通过；最终补齐人物选中状态下的重试按钮与正确原生绘制阶段截图。

首次构建的诊断空值警告、作业追踪器私有字段访问错误已修正；后者改为比较公开的 `HandlingPawn.jobs` 引用。未复制游戏或运行时 DLL。
